## 1. 一言でいうと

- **この本の問い**：
  AIの出力は毎回揺れる。
  それでも再現性のある開発をするには？
- **この本の答え**：
  開発を **Y = F(X)** の式で捉える。
  X（入力）→ Y（完成の判定）→ F（モデルの使い方）の順に制御する。
  3つはAI相互レビューで守る。
  → 「感覚」から「工学」へ。

## 3. 全体の骨格

```
問い：揺れるAIで、再現性ある開発を
 └ 答え：Y = F(X) を X→Y→F の順に制御
    ├ 土台：なぜ失敗し、どう捉えるか（1〜2章）
    ├ 柱1 X：入力を整える（3章）
    ├ 柱2 Y：完成をテストで定義（4章）
    ├ 柱3 F：モデルを編成して確率を上げる（5章）
    ├ 柱4 関所：AI相互レビューで3軸を守る（6章）
    └ 実装：個人のフロー（7章）→ 組織展開（8章）
```

- 章の流れ：`問題提起 → 枠組み → 解決策 → 実践`
- 核心の仕組み：**Yは次のXになる。**
  出来の悪いコードは、次の入力も悪くする（悪循環）。
  良いコードは次の入力も良くする（好循環）。

## 5. キーワード

| 言葉 | 意味（この本での使い方） |
|---|---|
| Y = F(X) | X：入力、F：LLM、Y：出力 |
| バイブコーディング | 感覚任せのAI開発。1章で代償を示す |
| LLMの2つの癖 | ①毎回出力が違う ②目の前のタスクにだけ最適化する |
| コンテキストエンジニアリング | Xを設計すること。定義は3.1 |
| コンテキスト品質の3原則 | 鮮度・必要十分性・一貫性 |
| 実装完了確率 | 揺れを数字で扱うための指標 |
| 並列実行／タスク割り当て | 確率を「数」で買う／「適材」で買う |
| WHATは人間、HOWはAI | テストで何を確かめるかは人が決める |
| 単一ゴール最適化 | テストだけでは足りない理由の1つ |
